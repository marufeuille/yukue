# yukue

メールで届く「ものの推移」だけを追うための、案件（エンティティ）トラッカーの設計とスキルの雛形。

注文・予約・請求・申込といった案件ごとに、「今どうなっているか」と「どう変わってきたか」を、根拠メールへの参照つきのタイムラインで見せる。全メールを読むための道具ではない。プロモーションやニュースは取り込まない。

## 全体像：3つの層

| 層 | 役割 |
|---|---|
| 本籍 | 案件とその遷移の記録そのもの。ここが残る |
| 橋 | メールから案件と遷移を抜き出す手順（スキル）。環境に合わせて差し替えられる |
| 知能 | 抜き出しと要約を担う AI エージェント。極論、なんでもいい |

配る単位は **本籍＋橋**。知能の層は受け手のエージェントが担うので、エージェントが代替わりしても道具は残る。

## 核の考え方

- 核はメールではなく **案件**。メールは遷移の根拠として案件にぶら下がる
- 案件はカードで持つ：現在の状態 ＋ 状態遷移のタイムライン
- 履歴を正とし、状態はそこから導く
- 止まったまま日数が経った案件は異常として目立たせる。正常な推移は静かに流れる
- 上段の「まとめ」も新しい実体ではなく、案件データからの射影（導出ビュー）に閉じる

## このリポジトリにあるもの

- `DESIGN.md` — 概要設計（思想レベル）
- `SCHEMA.md` — 案件と遷移のデータ構造
- `SKILL.md` — 受け手のエージェントに渡す抽出・表示スキルの雛形
- `DEPLOY.md` — 自分のインスタンスを立てる手順（yukue は個人用。共有インスタンスはなく、配布＝各自が自分のを持つこと）

実装そのものは含まれない。置き場（手元のアプリ内か、API の向こう側か）は未決事項として設計に残してある。各人の実装は、この設計とスキルの型に沿って自分の環境で持つ。
